# Connecting Ollama Across Two Machines

CodeGate needs a few thousand code samples generated by several different
LLMs. Rather than paying for API access, we run open models locally on
whichever machine has the better hardware, and the other machine drives it
over the local network.

- **HOST machine** — runs Ollama and the models. Needs the RAM/GPU.
- **CLIENT machine** — runs CodeGate, sends prompts to the host, collects
  and labels results. Needs almost nothing.

**Part 1 is for the host. Part 2 is for the client.** Do them in order —
Part 2 cannot be verified until Part 1 is finished.

Total setup time: ~20 minutes plus model download time.

---

# PART 1 — HOST machine setup

*(This is the section to forward to whoever is hosting the models.)*

## 1. Install Ollama

Download and install from **https://ollama.com/download** (Windows, macOS,
and Linux installers all available).

Verify it worked — open a terminal and run:

```bash
ollama --version
```

You should see a version number. If the command isn't found, restart your
terminal so the installer's PATH change takes effect.

## 2. Download the four models

Each is roughly 4 GB, so budget ~16 GB of disk and a decent chunk of time
on the first pull.

```bash
ollama pull qwen2.5-coder:7b
ollama pull deepseek-coder:6.7b
ollama pull codellama:7b
ollama pull starcoder2:7b
```

> **Short on RAM or disk?** Use the smaller variants instead —
> `qwen2.5-coder:1.5b`, `deepseek-coder:1.3b`, `starcoder2:3b`. This is
> genuinely fine, and arguably *better* for our purposes: smaller models
> write more varied and more insecure code, which is exactly the signal
> the experiment needs. Just tell the client which tags you pulled so the
> config matches.

**Rule of thumb:** a 7B model needs ~8 GB of free RAM to run comfortably.
A 1.5B model needs ~2 GB.

Confirm what you have:

```bash
ollama list
```

## 3. Make Ollama reachable over the network ⚠️

**This is the step everyone misses.** By default Ollama only listens on
`127.0.0.1` (localhost), meaning nothing outside your own machine can
reach it — the client will get "connection refused" no matter what else is
configured correctly.

You need to set `OLLAMA_HOST=0.0.0.0` so it listens on all interfaces.

**Windows:**
```powershell
setx OLLAMA_HOST "0.0.0.0"
```
Then **fully quit Ollama** — right-click its icon in the system tray
(bottom-right, near the clock) and choose Quit. Closing the window is not
enough; it keeps running in the tray. Then relaunch Ollama from the Start
menu.

**macOS:**
```bash
launchctl setenv OLLAMA_HOST "0.0.0.0"
```
Then quit Ollama from the menu bar and reopen it.

**Linux:**
```bash
sudo systemctl edit ollama.service
```
Add these lines in the editor that opens:
```
[Service]
Environment="OLLAMA_HOST=0.0.0.0"
```
Save, then:
```bash
sudo systemctl daemon-reload
sudo systemctl restart ollama
```

## 4. Allow the port through your firewall

Ollama uses TCP port **11434**.

**Windows** — open PowerShell **as Administrator** and run:
```powershell
New-NetFirewallRule -DisplayName "Ollama" -Direction Inbound `
  -Protocol TCP -LocalPort 11434 -Action Allow
```

**macOS** — you'll get a "do you want to allow incoming connections"
prompt the first time. Click Allow. (If you dismissed it: System Settings
→ Network → Firewall → Options → add Ollama.)

**Linux (ufw):**
```bash
sudo ufw allow 11434/tcp
```

## 5. Find your local IP address and send it over

**Windows:**
```powershell
ipconfig
```
Look for **IPv4 Address** under your active adapter (Wi-Fi or Ethernet).

**macOS / Linux:**
```bash
ip addr          # Linux
ifconfig         # macOS
```

You want the address starting with `192.168.` or `10.` — for example
`192.168.1.42`. Send that to the client machine's owner.

> Not the `127.0.0.1` one (that's localhost) and not a public IP.

## 6. Stop the machine from sleeping

A generation run takes several hours. If the laptop sleeps, the run dies.

- **Windows:** Settings → System → Power & battery → Screen and sleep →
  set *"When plugged in, put my device to sleep after"* to **Never**.
- **macOS:** System Settings → Displays → Advanced → enable *"Prevent
  automatic sleeping on power adapter when the display is off"*.
- **Linux:** Settings → Power → Automatic Suspend → Off (when plugged in).

Keep it plugged into power. You can close the lid on most setups as long
as sleep is disabled, but leaving it open is safer.

**Host setup is done.** You don't need to do anything else — no CodeGate
install, no Python, nothing. Just leave Ollama running.

# PART 2 — CLIENT machine setup

## 7. Verify you can actually reach the host

**Do this before anything else.** Nothing downstream works until this
returns data. Replace `192.168.1.42` with the IP you were given:

```bash
curl http://192.168.1.42:11434/api/tags
```

**Expected:** a JSON blob listing the four models.

**If it doesn't work**, the failure mode tells you which step to revisit:

| Symptom | Cause | Fix |
|---|---|---|
| Hangs, then times out | Firewall is blocking the port | Host redoes step 4 |
| `Connection refused` | Ollama still bound to localhost | Host redoes step 3 — including the **full quit and relaunch** |
| `No route to host` | Machines aren't on the same network | See the networking note below |
| Returns JSON ✅ | Working | Continue to step 8 |

> **Networking note:** both machines must be on the same LAN. Public and
> university Wi-Fi very often enable *client isolation*, which blocks
> device-to-device traffic entirely and cannot be worked around from
> either machine. If you're on campus Wi-Fi and `No route to host` won't
> go away, use a phone hotspot with both machines connected to it, or
> plug both into the same router by Ethernet.

## 8. Point CodeGate at the host

In the CodeGate repo root, create a file named `.env` (copy `.env.example`
if you'd rather start from that) containing:

```
OLLAMA_BASE_URL=http://192.168.1.42:11434
```

Use the real IP. No trailing slash. This file is gitignored — it never
gets committed.

## 9. Smoke-test with five samples

Never start a multi-hour run without checking the small case first:

```bash
python scripts/run_real.py --limit 5 --out-dir data/runs/smoke
```

This generates five snippets and labels them. It should finish in a couple
of minutes. Open `data/runs/smoke/generations.parquet` and confirm the
code looks like real model output — actual Python, varying between
samples, not empty strings.

## 10. Launch the real run

Once the smoke test is clean:

```bash
python scripts/run_real.py --out-dir data/runs/real_540 > logs/generation.log 2>&1 &
```

Redirecting to a log file means closing your terminal won't kill the run.
Watch progress with:

```bash
tail -f logs/generation.log
```

**Expected duration:** roughly 2–5 hours for 540 samples on CPU, much
faster if the host has a GPU. The run checkpoints as it goes, so a dropped
Wi-Fi connection loses at most the sample in flight, not the whole run.

---

## Afterwards: close the door

The setup above leaves an **unauthenticated service exposed on the local
network** — anyone on the same Wi-Fi could send requests to it. That's an
acceptable trade for a few hours on a trusted network, but don't leave it
open indefinitely.

When the run is finished, the host should remove the firewall rule:

**Windows** (Administrator PowerShell):
```powershell
Remove-NetFirewallRule -DisplayName "Ollama"
```

**Linux:**
```bash
sudo ufw delete allow 11434/tcp
```

And optionally revert `OLLAMA_HOST` back to `127.0.0.1` the same way it
was set in step 3.

```bash
curl http://<host-ip>:11434/api/tags
```
